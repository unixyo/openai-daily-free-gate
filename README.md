# openai-daily-free-gate

A small local proxy that stops OpenAI API text requests before they exceed the
**daily complimentary-token limits** OpenAI offers to organizations that share
API traffic with OpenAI (the "data sharing" program).

It runs on `127.0.0.1`, keeps a per-day token ledger in SQLite, and refuses a
request *before* it reaches OpenAI when that request could push the day's total
over the configured cap. Python standard library only, no dependencies.

## What it does

- Accepts text-only requests on `POST /v1/responses` and
  `POST /v1/chat/completions`, including SSE streaming, and forwards them over
  HTTPS to `https://api.openai.com`.
- Allows only model IDs on its built-in allowlist (taken from the official
  complimentary-token list), split into the two official groups:
  - **big group**: official Build limit 250,000 tokens/day, gateway default cap **240,000**
  - **small group**: official Build limit 2,500,000 tokens/day, gateway default cap **2,400,000**
- Before forwarding, reserves a conservative estimate: UTF-8 byte length of the
  request JSON + 2,048 tokens headroom + the requested max output tokens
  (default 2,048, maximum 8,192). If `used + in-flight + reservation` would
  exceed the cap, it returns HTTP 429 and sends nothing upstream.
- After the reply, records the real `usage` total reported by OpenAI. If usage
  cannot be read (for example a dropped stream or a 5xx error), the full
  reservation is charged. Upstream 4xx errors are charged 0.
- Starts a new ledger at 00:00 UTC each day (09:00 in Korea), matching the
  official reset time.
- Rejects requests that can be billed outside the grant or cannot be
  cost-checked: tools/function calling, web search, images, audio, files,
  `modalities`, `prediction`, non-default `service_tier`, `background`,
  stored conversations / `previous_response_id`, `n` or `best_of` other than 1.
- `GET /v1/models` asks OpenAI for your real model list (using the key your
  client sends) and returns only the models that are both on the allowlist and
  actually available to you. No tokens are generated by this call.
- For GPT-5 / GPT-6 / o3 models on Chat Completions, rewrites the legacy
  `max_tokens` field to `max_completion_tokens` (some OpenAI-compatible clients
  still send `max_tokens`). The reserved budget is unchanged.
- Never stores, logs or prints your API key. Request logging is disabled, and
  upstream error bodies are not logged.

## What it does NOT do

- **It cannot stop programs that call the OpenAI API directly.** Only requests
  sent through this proxy are counted or blocked. The Playground, other apps,
  other machines and scripts that talk to `api.openai.com` directly are
  invisible to it.
- **It does not know your real organization usage.** OpenAI applies the free
  limit to the whole organization. If something else used part of today's
  grant, requests through this proxy can still be billed even when the local
  ledger shows room left.
- It does not import usage that already happened today.
- Its input-token estimate is a conservative approximation, not the official
  tokenizer. It is designed to overestimate, but unusual payloads are not
  guaranteed to be measured exactly.
- It does not check whether data sharing is enabled for your project or
  whether your organization is eligible.
- It does not update its model allowlist automatically. New, renamed or
  aliased models are refused until you edit `BIG_MODELS` / `SMALL_MODELS` in
  `gate.py`.
- It does not proxy embeddings, images, audio, files, fine-tuning, evals,
  batch or any endpoint other than the two above.
- It is not a security boundary for untrusted users. It listens on localhost
  only and has no authentication of its own beyond passing your key through.

## How the limits were chosen

Source: OpenAI Help Center,
[Sharing feedback, evaluation and fine-tuning data, and API inputs and outputs with OpenAI](https://help.openai.com/en/articles/10306912-sharing-feedback-evaluation-and-fine-tuning-data-and-api-inputs-and-outputs-with-openai),
section "Complimentary tokens on prompts and completions shared with OpenAI"
(read on 2026-10-29 and re-checked 2026-10-30). Related:
[OpenAI developer docs](https://developers.openai.com/api/docs/guides/chatgpt-api-credits).

At the time of writing, that page says:

- Each model group has its own daily limit, shared across the models in that
  group.
- Build organizations: 250,000 tokens (first group) and 2,500,000 tokens
  (second group). Launch and Grow organizations: 1,000,000 and 10,000,000.
- The counter resets at 00:00 UTC.
- If one request would push the day's total over the limit, **that entire
  request is billed** at normal rates.
- Fine-tuned models, fine-tuning training, evals and tool use are not included.

From that, the gateway:

- uses the **Build** limits as the hard ceiling (`--big-cap` may not exceed
  250,000 and `--small-cap` may not exceed 2,500,000). Launch/Grow
  organizations are therefore held to the smaller Build numbers;
- defaults to 96% of the limit (240,000 / 2,400,000), leaving 4% for usage
  outside the proxy and for estimate error;
- reserves the worst case before each request, because one request that
  crosses the line is billed in full;
- blocks tools, because tool use is excluded from the grant.

The allowlist in `gate.py` is a subset of the models on the help page. The
page also lists some models the gateway deliberately does not allow (for
example retired snapshots). Compare the two lists yourself before use.

## Requirements

- Python 3 (standard library only). Tested with Python 3.14 on Linux.
- An OpenAI API organization with data sharing enabled and the message
  "You're enrolled for complimentary daily tokens" shown on its data-sharing
  settings page.
- Optional: systemd (user service) to run it in the background.

## Install and run

```sh
git clone <this-repository-url> openai-daily-free-gate
cd openai-daily-free-gate
python3 gate.py
```

The gateway listens on `http://127.0.0.1:18765/v1`. Options:

```sh
python3 gate.py --port 18765 --big-cap 230000 --small-cap 2300000 --db .state/usage.sqlite3
```

| Option / variable | Default | Meaning |
| --- | --- | --- |
| `--port` | `18765` | Local port (always bound to 127.0.0.1) |
| `--db` | `.state/usage.sqlite3` next to `gate.py` | Ledger file; survives restarts |
| `--big-cap` | `240000` | Daily cap for the big group (max 250000) |
| `--small-cap` | `2400000` | Daily cap for the small group (max 2500000) |
| `GATE_UPSTREAM` env | `https://api.openai.com` | Upstream base URL |

See `.env.example` for placeholder values. The gateway does not read
`OPENAI_API_KEY`; your client sends the key.

### Connect a client

Set your OpenAI-compatible client's base URL to `http://127.0.0.1:18765/v1`
and keep your API key in the client's normal secret setting (for example the
`OPENAI_API_KEY` environment variable). Do not type the key into shell
history.

```python
from openai import OpenAI

client = OpenAI(base_url="http://127.0.0.1:18765/v1")  # key from OPENAI_API_KEY
result = client.responses.create(
    model="gpt-5.6-terra", input="Hello", max_output_tokens=1024
)
print(result.output_text)
```

This example makes a real, billable-if-over-limit API call once connected.

### Check status

```sh
curl -s http://127.0.0.1:18765/status   # JSON
python3 status.py                       # readable summary (Korean UI)
python3 status.py --watch 5             # refresh every 5 s, Ctrl+C to stop
python3 status.py --no-models           # remaining tokens only
```

`status.py` only reads the local `/status` endpoint. It needs no key and uses
no tokens. `GET /health` returns a simple liveness check.

### Run as a systemd user service (optional)

```sh
mkdir -p ~/.config/systemd/user
cp systemd/openai-daily-free-gate.service.example ~/.config/systemd/user/openai-daily-free-gate.service
# edit the paths in the copied file if the repo is not at ~/openai-daily-free-gate
systemctl --user daemon-reload
systemctl --user enable --now openai-daily-free-gate
systemctl --user status openai-daily-free-gate
```

If the service is stopped, clients pointed at the fixed base URL get a
connection error. Check whether your client silently falls back to another
provider or URL in that case. Running `gate.py` by hand while the service is
up fails with an address-in-use error.

## Tests

```sh
python3 -m unittest -v test_gate.py
```

The tests start a fake OpenAI server on localhost. They make no network calls
to OpenAI and use no credits.

## Recommended setup

1. Use a dedicated OpenAI project and API key only through this proxy.
2. Keep other API apps on that organization off the free models, or account
   for them by lowering the caps.
3. On first use, open the
   [Usage dashboard](https://platform.openai.com/usage/chat-completions),
   group by "service tier", and confirm the traffic shows as
   "data sharing incentive tier".
4. Compare with
   [Credit grants / billing](https://platform.openai.com/settings/organization/billing/overview).
5. Re-read the help page from time to time and update the allowlist and caps
   when it changes.

Data you send through a data-sharing project is shared with OpenAI. Do not
send sensitive, confidential or personal data.
